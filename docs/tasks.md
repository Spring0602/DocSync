## 原实施顺序与交接格式

以下前两步针对现有 20 样本已完成；新增正式样本仍按相同独立标注流程执行。当前优先事项以顶部表格为准。

1. **现在并行：** B-N1 与 C-N1 独立标注；A 准备模型和指标口径。标注时不看彼此答案。
2. **接着并行：** B 修复英文句式，B/C 协作到期日契约与展示；C 验证 Action 和第二设备；A 收表后裁决。
3. **代码和数据准备好后：** A 冻结适当的数据版本，完成真实小样本及主实验；B/C 回归并提供证据。
4. **最后：** A 作最终验收，C 统一发布材料，确定发布提交/tag。当前开发集、开发 SHA 和 Core CI 记录不直接升级成正式发布结论。

交接至少包含：任务编号、完整提交 SHA、改动范围、执行命令、通过/失败/跳过数、产物路径或有效链接、未解决事项、接收人下一步。运行目录通常不入库；需跨设备审核的精简证据放 docs/audit-samples，确认不含密钥或个人信息。

已完成的技术工作沿用既有证据，只有代码变化、失败或未解决问题才重跑相关检查。已知标注接触情况、开发标签和工具预测必须披露；不得将补填标注称为从未接触过数据的盲测。
