## 计分方案草案（初始设计；实现进展见文末）

1. 单位为固定文档声明，不是仓库的一切诊断。保存 sample_id、固定 SHA、文档焦点跨度、目标接口/配置键及别名、允许的代码证据集合。17/18/20 保存生成链；22 保存默认配置和句柄转发链。gold、理由和代码证据映射只用于评测，不注入模型提示。
2. 在六个固定仓库上按方法扫描，记录完整上下文范围和配置。相同仓库/配置/方法的报告可供该组多个不同声明读取，调用及成本按实际扫描计一次。未决 10 不参与分母，但不删改源码或文档中的相关上下文。
3. 预测必须匹配声明跨度与目标语义；仅同 README、同 drift_type 或其他函数发生冲突不算本条命中。导出名与实现名按冻结别名映射处理，生成接口不能凭字符串同名匹配。多条不相容判断保留歧义；一个仓库级发现不能未经逐条匹配复制为多条预测。
4. 没抽到目标声明记 SKIPPED，有判断但证据不足记 UNCERTAIN；不把无发现/拒答当明确一致。失败及 PARTIAL 原样保存，分别报告运行完整率、明确一致率、误报率和拒答/未抽取率。
5. 当前已解决分母为 23（各组 4/4/3/4/4/4），声明级和六仓库级汇总分别展示，不能把相关样本当独立抽样计算结论。冲突召回与证据不足表现记不适用；现有 metrics 的 TN 包含拒答，不能当明确判对数。
6. 七方法、最终代码 SHA、每仓库扫描范围、方法差异、请求/token/费用预算及失败处理必须在执行前冻结。不能沿用旧按样本重复扫描的请求预算来宣称新方案成本。

## 现有工具与方案的差距

`src/docsync/benchmark.py` 的 BenchmarkSample 只有单一 claim_line，无目标实体字段。predict 按文档路径/起始行定位；claim_line=None 会选整份文档，不能直接用于共享 README 的本批样本。keyword 也仅看单行或整份文档。当前 runner 每个样本重复扫描仓库，与上面的按仓库复用方案不同。

正式执行前需要实现并用与 external-v1 无关的合成测试验证声明映射、实体别名、跨段证据、未抽取/歧义和报告复用；这属于评测基础设施，不借真实样本扫描结果调整检测器。当前包只是文本证据集合，不是可直接运行的完整仓库 manifest；应从已固定 Git 提交构建扫描输入，保留原始路径和版本，禁止导入/执行上游代码。
