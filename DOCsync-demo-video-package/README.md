# DocSync 本地报告工作区

这个前端用于审阅 DocSync CLI 生成的报告，不是网页扫描引擎。它支持导入自己的报告、跨页查看同一份数据、搜索问题、核对证据、下载补丁 diff 和比较复扫报告。

## 打开

Windows：完整解压后双击本目录的 **启动前端.cmd**，保留弹出的终端窗口。浏览器会自动打开；若没有打开，把终端中的本机 URL 复制到地址栏。

项目根目录或交接包根目录也可运行：

~~~text
python scripts/serve_frontend.py
~~~

只打开前端需要 Python 3.12 或更新版本；运行 DocSync 核心扫描需要 Python 3.12 和项目依赖。前端没有 npm 安装步骤，不需要 API 密钥。Ctrl+C 关闭本地服务。

启动器只绑定本机地址，只公开前端白名单文件。它不提供上传或修改接口，不开放项目根目录、标注表和密钥。**不要从包含私人资料的项目根目录运行无范围限制的静态服务器。**

不装 Python 也可以双击 demo-ui/index.html 查看内嵌演示，但 file:// 下的跨页会话存储依赖浏览器行为，推荐启动器。

## 页面与用法

| 页面 | 可以做什么 |
| --- | --- |
| 首页 | 了解能力边界，进入当前报告或阅读使用步骤 |
| 数据 | 按路径搜索快照文件，查看真实哈希和计数 |
| 证据 | 选择不同记录，并排阅读报告内的源码表达式与文档原文 |
| 运行 | 查看当前扫描与可选复扫的轨迹，不虚构 Git 日志 |
| 报告 | 导入、搜索、筛选、分页，展开问题、证据、补丁和复扫对照 |

1. 打开“报告”，点击 **导入 report.json**，选择 CLI 生成的完整 JSON 文件。
2. 根据文件路径、参数或原因搜索，或按状态、类型筛选。
3. 点击一条记录，再展开“证据对照”。不确定和验证拒绝记录也可以查看，不会被隐藏在零告警后面。
4. 在“建议补丁”中审阅 diff。网页可下载或复制，但不会应用修改；CLI 应用还需要原始 patch manifest。
5. 在“验证记录”中导入复扫报告。必须来自同一仓库、同一基准提交、兼容配置与扫描类型、不同运行 ID。提交模式到工作树模式的复扫允许对比。
6. 通过页面导航进入数据、证据和运行页；它们读取当前标签页会话的同一份报告。点击“恢复演示”会清除该应用的导入缓存。

导入上限为 10 MB。缓存基于浏览器 sessionStorage，不是长期存档；关闭标签页、重启服务改变端口或浏览器恢复策略都可能影响会话。需要保留时先下载 JSON。存储满或不可用时会明确提示，当前页面仍可使用。

## 四个数字

- 确认冲突：判断为 INCONSISTENT、验证为 VERIFIED、未忽略的 Finding 数。
- 建议补丁：报告提供的 PatchProposal 数，不代表修复成功。
- 不确定项：UNCERTAIN 等不确定判断与验证拒绝记录的 claim_id 并集，避免重复计数。
- 已忽略项：明确标记 ignored 的 Finding 数。过期忽略规则不计入。

缺失字段显示“未记录”或破折号，不补成零。PARTIAL 和 FAILED 会突出提示。结构可读不等于证据真实，零冲突不等于全部声明已验证一致。

## 默认演示的来源

demo-data.js 内嵌已有的真实 CLI 前后报告；原始文件在 artifacts/。演示显示 1 条默认值冲突、1 份补丁、复扫 0 条冲突、规则模式 0 模型请求。

这些是**已有归档工件**，不是本轮界面改动后重新生成的结果。其依赖版本以 manifest.versions 为准，与项目当前固定依赖可能不同。本轮当前源码的全流程检查另有独立记录，不覆盖历史工件。不要修改数字后仍称其为原始运行结果。

## 文件说明

~~~text
demo-ui/
  index.html / data.html / code.html / history.html / reports.html
  report-store.js        共用结构校验、计数、会话与复扫可比性
  portal.js / portal.css 首页及数据、证据、运行页面
  app.js / styles.css    报告工作台
  demo-data.js           内嵌历史真实工件
  tests/                数据契约回归测试（开发源码内提供）
artifacts/              归档前后报告和补丁
启动前端.cmd            调用上一级 scripts/serve_frontend.py
给队友-打开与修改.md     小白操作与交接说明
~~~

不要只发一个 HTML 或只复制本目录里的 CMD。交接包需要保留上一级 scripts/serve_frontend.py 和本目录的相对层次。主项目提供 scripts/package_frontend.py，按白名单生成独立前端 ZIP，不带私人标注和本地环境。

## 验证与边界

本轮使用 Node 原生测试验证数据契约，使用真实 Chromium 验证导入、异常输入、跨页会话、搜索分页、忽略到期、复扫和导出。布局检查涵盖 320、390、768、1024、1440 像素。完整项目中的 scripts/qa_frontend.cjs 可复跑浏览器测试，需要另行提供 Playwright 与浏览器；日常使用不需要这些开发依赖。

本地前端服务不是生产 Web 服务。没有用户账户、云同步、扫描后端或在线补丁执行。缺失的源码摘录不会推测生成。报告只做结构校验，页面内“已验证”沿用原报告，不代表浏览器重跑验证器。

界面使用本地系统字体和代码内 SVG 图标，不加载外部字体、图标库或图片。代码和说明由 Codex 辅助修改，并进行了自动测试和浏览器检查；团队仍应审核后再提交，不应把 AI 辅助开发写成独立人工完成。
