# DocSync 3-5 分钟演示视频脚本

> 建议成片：4 分 20 秒至 4 分 40 秒，1920×1080，浏览器缩放 90%-100%。
> 页面用于可视化真实 CLI 工件，不宣称浏览器直接执行扫描或写入仓库。
> 视频、技术报告和答辩材料不得出现学校名称、学校 LOGO 或指导教师信息。

## 录制前准备

1. 在项目根目录运行 README 的“五分钟跑通”，确认扫描、补丁、应用和复扫全部成功。
2. 用本地静态服务器打开 `DOCsync-demo-video-package/demo-ui/index.html`，先展示精简项目首页，再点击“打开问题报告”。
3. 检查页面标题下显示“随包演示报告 · 只读”，并确认 `artifacts/` 中有前后报告和补丁清单。录制讲解时使用手动导航，不开启快速导览。
4. 关闭无关通知、浏览器书签栏和个人账号信息。

## 0:00-0:25 开场：真实问题与用户价值

画面：项目标题或审计台首页。

口播：

> DocSync 是一个面向 Python 和 Markdown 的代码-文档一致性检测工具。代码迭代后，默认值、调用签名和配置说明很容易过期；人工检查成本高，简单关键词搜索又容易把合法调用误判为错误。DocSync 用“固定快照、静态事实、独立验证、最小补丁、复扫确认”建立可追溯闭环。

## 0:25-0:55 第一步：锁定 Git 快照

操作：保持左侧“概览”选中，展开“查看报告标识与诊断”。

重点指向：

- 顶部 commit 提交；
- rules 模式；
- Schema 2.0；
- 随包演示报告提示；
- 0 次模型请求。

口播：

> 演示数据不是手工编出的页面数字，而是当前源码真实 CLI 运行后保存的报告。扫描从固定 Git 提交开始，文件、行号、字节范围和 blob hash 都绑定到同一快照。离线规则模式不需要模型密钥，也不会执行被扫描项目中的 Python 代码。

## 0:55-1:55 第二步：扫描并验证证据

操作：点击左侧“证据”或“下一项”。

画面：并排展示源码与文档；默认值分别突出显示为 60 与 30。源码行号为 L4–5，事实字节范围为 93–95，不要混淆。

口播：

> `src/client.py` 中 `connect` 的真实默认值是 60，而 README 第 5 行声明默认值为 30。DocSync 从 Python AST 提取事实，从 Markdown 提取明确声明，再通过确定性对齐和独立验证确认冲突。每条 Finding 都保留路径、行号、字节范围、文件哈希、规则版本和稳定 ID。

补充说明：

> README 还包含 `connect(timeout=30)` 的显式调用示例。显式传参可以覆盖默认值，因此它不是“默认值为 30”的证据，DocSync 不会把它误判为第二条冲突。面对动态表达式或证据不足的情况，系统返回不确定，而不是静默猜成一致。

## 1:55-2:50 第三步：审阅最小补丁

操作：点击左侧“补丁”或“下一项”。

画面：原始 unified diff 展示修改前后行号；展开“补丁校验记录”可查看明细。

口播：

> 对已验证冲突，DocSync 生成最小文档补丁，只把目标声明中的 30 改成 60，不修改合法调用示例。补丁绑定原始 blob hash 和字节 preimage，并经过代码围栏保护和内存复扫。它仍标记为“需人工审阅”，必须由人审阅后显式执行 apply。

强调：

> 如果文件已经变化、补丁被篡改、路径越界，或者旧补丁重复应用，系统会拒绝写入；多文件写入异常时执行回滚。

## 2:50-3:35 第四步：工作树复扫闭环

操作：点击左侧“复扫”或“下一项”。

画面：“验证记录”中出现独立复扫运行；右侧展示“1 → 0 条确认冲突”、不确定项及复扫耗时。顶部仍是原扫描的统计，不会被导览改写。

口播：

> 应用补丁并不等于问题已经关闭。DocSync 使用 `--working-tree` 重新扫描修复后的文件。随包复扫报告证明：状态 COMPLETED，确认冲突从 1 变成 0，不确定项仍为 0。旧补丁再次应用会触发 STALE_PATCH。

## 3:35-4:05 真实报告导入与开放成果

操作：点击“导入报告”，选择 `artifacts/before-report.json`；重新展示真实证据。

口播：

> 这个页面不仅能展示随包案例，还能在浏览器本地读取完整的 DocSync `report.json`，当前上限 10 MB。文件不会上传，报告中的验证状态也不会被页面重新计算。多条告警可以切换查看；单独导入修复前报告时，页面会等待复扫记录，不会伪造修复成功。项目开放了核心代码、CLI、GitHub Action、报告 Schema、评测脚本、测试用例和技术文档，方便其他团队复用和二次开发。

## 4:05-4:30 收尾：AI 与开源融合价值

口播：

> DocSync 的核心不是简单包装模型，而是可复现的静态分析、证据绑定、拒答机制和安全补丁闭环。默认规则模式完全离线；混合模式可以接入模型服务，但模型不能绕过独立验证。它适合本地 CLI、持续集成和开源协作中的文档质量门禁。

画面：回到完整审计台，停留 3-5 秒结束。

## 视频自检

- 总时长 3-5 分钟，MP4，不超过 300MB。
- 展示核心功能、操作流程、实际效果和开放成果。
- 不出现学校名称、学校 LOGO、指导教师、API 密钥或个人账号信息。
- 不把静态页面动画表述为浏览器内真实执行 CLI。
- 字体、代码、哈希和状态在 1080p 下可读。
- 报告中的测试数字与仓库工件完全一致。
