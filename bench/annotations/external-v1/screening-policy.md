# external-v1 第一轮具体样本筛选规则

制定日期：2026-10-11。适用于已由成员 A 接受的六个固定提交；在本轮读取候选代码/文档正文前写入。来源发现阶段仅看过路径、元数据、许可证及 Rich 的 AI 政策。

1. 仅从 sources.jsonl 的文档入口按文件登记顺序、文档行号升序筛选。每仓库最多取四个互不重复的声明单元；不足四个不补造，不按标签类别凑数。相同接口/事实的重复示例只保留首次符合条件的单元。
2. 单元须有 Markdown 原文中的明确默认值/配置描述，或可定位目标的具体 Python 调用。只有宣传、效果图片、安装/命令行步骤、没有关联接口的叙述不纳入；不将“工具能抽取”设为条件，不运行 DocSync 或模型来筛选。
3. 先固定文档声明，再定位同提交的相关源码；必要的导出、配置、包装器等上下文可以扩展读取，但必须记录。动态默认值、装饰器、环境依赖不是排除理由，保留给标注者判断；找不到对应源码/无法确定评估对象时记录排除或暂缓。
4. 每个单元明确一个评估问题、文档焦点坐标、相关代码入口及完整文件哈希。焦点不裁剪原文、不替换上下文、不预填真值或推理。不得执行目标仓库代码，也不检索缺陷答案。
5. 同仓库的单元全部使用同一 provisional group；同源/派生/模板家族是否跨仓库及与旧开发集重叠仍需复核。核对两个已冻结开发集的 ID、repo、group 和文件哈希，不能凭不相等即声称独立。
6. 每个纳入文件保存完整固定 Git blob、上游许可证和来源 URL；逐文件检查可见版权/许可声明。只按已确认开源授权留存，不把上游作品改授 Apache-2.0。存在额外限制时先记录待处理，不发布该材料。
7. B/C 分别收到相同原文与各自空表；表中标签、类型、证据、理由、日期、审核人、最终坐标/实体均留空。接触情况另填。未完成双标、A 裁决及权利/独立性审查前 formal_test_ready=false，不设 split=test，不进入实验。

限制：这是固定入口的目的性小样本收集，最多 24 个单元，不是随机抽样或预设类别均衡。采集助手见过 DocSync 开发历史且辅助筛选；不能证明来源未进入模型训练集，也不能替 B/C 声明独立人工标注。自然来源不保证存在足够冲突样本。
